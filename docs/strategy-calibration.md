# Calibration runs

## Missing-quote policy

All calculation paths apply the [global derived missing-quote policy](missing-quotes.md) before the availability/gap rules described here. Arithmetic smoothing is the default; seeded normal log-return sampling is selectable in Settings. Raw saved evidence and existing reports remain unchanged. References below to missing/invalid prices mean prices still unavailable after this bounded policy.

**Calibration** (`#/calibration`) is the signed-in user's history of successful
calibration runs, newest-started first, in pages of 20. Each row shows the run
date, saved strategy name, simulation method, evaluation policy and parameters, Brier score,
calibration error and scored-scenario count. Multiple runs of the same strategy remain separate.

**New run** (`#/calibration/new`) lets you choose a strategy, configure its
parameters and settings, then explicitly **Run calibration**. A successful run
opens its read-only report at `#/calibration/{runId}`, including the original
settings, actual seed, scores, calibration curve and complete paginated audit.
**Run again** opens `#/calibration/new?from={runId}` with those settings prefilled;
you may edit them before running. It never changes the original report.

Reading history or a report never calculates, acquires instruments, or requires
the saved strategy/instrument to remain available. Starting another run rechecks
current strategy support and acquired membership. Failed calculations do not
create successful reports or erase history. Navigating away aborts the browser's
request, not necessarily server-side work; a successful run may still appear in
history. Old `#/strategies` links open history; old strategy-detail links open a
new-run form with that strategy selected.

Calibration generates **1,000 goal scenarios** by default (10–5,000), with
3–24-month horizons and a 12-month training lookback. There is no single-scenario
UI or public API. Choose **Standard Monte Carlo** (the default) or **Block
bootstrap** separately from the strategy. Bootstrap offers 5-, 10- (recommended),
and 20-trading-day shortcuts plus a custom integer block size of 1–60.
Optional settings control horizons, lookback, origin-date bounds and the seed. A blank seed is generated by the server; **Generate seed** changes
it without calculating. Reusing a seed reproduces scenarios and forecasts while
history, settings and numerical implementation are unchanged.

## Scores

The event is **reaching a financial goal**, not positive return or profitability.
For each scored case, `p` is the predicted probability and `y` is 0 or 1:

```
Brier score = mean((p - y)^2)
Calibration error = sum_b((n_b / N) * abs(mean_p_b - observed_rate_b))
```

Calibration error is **expected calibration error (ECE)** over the same ten
fixed-width probability bins used by the curve. It measures the average absolute
vertical gap from ideal calibration, weighted by scored cases. Empty bins do not
contribute. It is not the signed average gap, unweighted bin average or mean
predicted probability. Both metrics range from 0 (best) to 1; ECE is displayed in
**percentage points**, so `0.042` appears as `4.2 pp`.

Bins are `[0, .1)`, `[.1, .2)`, …, `[.9, 1]`. Each nonempty bin plots its mean
predicted probability against observed success frequency. Empty bins have null
coordinates and no chart point. Counts refer to generated cases, not simulation
paths. ECE depends on this binning and sample mix; it is a summary of the curve,
not a profitability ranking.

## Scenario generation

1. Find monthly origins with a full lookback and enough remaining calendar
   coverage for the minimum horizon. Allocate cases evenly, using a seeded random
   order for subsets/remainders. Allocation uses dates only, not future price
   quality or outcomes. Invalid assigned cases are excluded, never replaced.
2. Generate starting capital uniformly in cents from EUR 1,000–100,000. Generate
   the final goal uniformly in cents from **capital + EUR 0.01** through
   EUR 1,000,000: the goal is always strictly higher than the starting capital.
   Generate a whole-month horizon within the requested range that fits saved
   calendar coverage, and a requested success rate across ten strata from 1%–99%.
   These draws do not depend on market price values or the simulation method.
   The same seed, date bounds and scenario settings produce the same test inputs
   for standard Monte Carlo and block bootstrap.
3. Fit each origin's model on its trailing training prefix only. Use the selected
   method to simulate 10,000 paths and **solve the required EUR/month** with the
   same contribution quantile and upward cent rounding as the goal planner.
   Monthly funding is an output, never a random input. The target is never
   obtained from a simulation quantile. Numerically unstable or above-limit
   funding returns a validation error, never clipped or replaced with a different test.
4. Estimate the solved funding plan's actual success probability using a separate,
   independent 10,000-path stream of that same method. This prevents scoring the
   solution only on the draws that selected it. Requested probabilities remain
   distinct from actual predictions; zero funding, flat histories and cent
   rounding can leave bins empty. Coverage is not fabricated.
5. Freeze the test inputs, solved contribution and prediction, then replay that
   funding plan on the later historical prices. Brier and ECE weight scored cases
   equally. No future prices are used to choose funding or test inputs.

Root seed, origin date and date-local case number identify parameter draws.
Scheduling, scenario inputs, contribution solving and probability estimation use
separate RNG domains. Two growth/annuity streams are shared across funding cases at each
origin, avoiding thousands of complete simulations. Increasing count preserves
common case IDs/definitions when other settings and history are unchanged.

The audit contains every generated case's inputs, requested and actual
probabilities, training/valuation dates and outcomes. Exclusions retain their
case IDs and reasons. UI pagination limits rendered rows, not metric inputs.

## Historical calculation

- Read saved quotes for the selected symbol/MIC, latest per date at the calculation
  cutoff, breaking collection-time ties by descending `_id`. Ignore later price
  and collection dates. Never acquire data or spend provider quota.
- Forecast at the first recorded weekday of each month. Origin-date bounds do not
  filter training or outcome dates. Fit only the trailing window ending at the
  origin, with a full calendar lookback and at least 60 usable daily returns.
- Saved provider split snapshots plus [manual split corrections](on-demand-market-data.md#manual-splits)
  supply a separate `split_adjusted_close` series for both training and realized
  cash-flow ratios. Manual-only legacy histories explicitly warn about incomplete
  coverage; conflicting manual/provider factors block calculations. Multiply raw closes by
  cumulative effective split factors; future actions do not alter earlier prefixes.
  Cash distributions are not reinvested. Legacy history without splits retains
  training-selected adjusted/raw basis with a download warning. The training
  prefix determines currency eligibility. Never use cached full-history statistics
  or change basis because later prices are missing. A current EUR override fills missing currency only, not
  explicit foreign currencies.
- Standard Monte Carlo uses the planner's independent normal log-return model.
  Block bootstrap draws complete contiguous blocks of observed daily log returns
  **only from each origin's trailing training prefix**, preserving within-block
  ordering, split-corrected price basis and gaps. Contribution-solving and prediction
  use independent seeded block streams; neither sees later outcomes. An origin
  whose training has 60+ usable returns but no uninterrupted run long enough
  for its chosen block is excluded as `insufficient_block_history`, not silently
  simulated with a smaller block or a normal fallback. Both methods approximate
  252 trading days/year using calendar days/365.25. Starting capital is invested
  at the origin; contributions arrive on monthly anniversaries.
- Historical contributions buy at the first saved weekday close on/after their
  due date. Uninvested deposits remain cash. Value at the last close on/before
  the goal date, never a later quote. Missing/invalid execution or valuation
  prices, gaps over seven days, and conflicting currencies exclude the case.
- Goal success is checked before display rounding. Growth/annuity accumulation,
  accurate cash-flow summation and an eight-ULP subcent tolerance preserve exact
  funding without turning a one-cent shortfall into success.

### Interpretation

Walk-forward fitting on downloaded data is not strict historical-vintage data:
provider revisions, adjustments, current instrument selection and currency labels
can embed later information. Overlapping horizons, reused market paths and
shared simulations mean scenarios are not independent observations. The distinct
historical-origin count reports the available date support; generating more cases
improves coverage, not independent evidence. Missing outcomes can bias the scored
subset. Choosing settings or seeds after inspecting scores is hindsight selection.
Across methods, generated capital/goal/date/rate inputs are identical for a fixed
seed, but solved monthly contributions (and therefore realized outcomes) can differ:
the score evaluates each method's recommended funding plan. Compare common scored
scenario IDs and inspect exclusions when comparing methods, not only aggregate
scores. Legacy simulated-target runs use a different policy and are not comparable.
Block bootstrap can preserve short-range dependence and observed tail events but
cannot invent unobserved events or ensure future regimes resemble training.

Calculations assume nominal EUR, frictionless fractional holdings, no FX
conversion, taxes, fees or inflation. Model payments use calendar anniversaries;
historical execution rolls to recorded closes, without an exchange calendar.
Details stay here and in the API audit, rather than repeated UI explanations.

## API and persistence

All routes require the normal session; POST also requires same-origin protection.

- `GET /goals/calibrations?limit=20&offset=0`: `{items, total, limit, offset}`,
  with compact run summaries only, ordered by calculation start order descending
  and unique ID as a tie-breaker. Limit is 1–100; offset is nonnegative. Summaries
  contain `id`, `strategy_name`, `strategy`, `settings`, `seed`, `calculated_at`,
  `brier_score`, `calibration_error`, `sample_count`, `origin_count` and (for newly
  saved runs) compact `generation` metadata, not audit
  rows or chart arrays.
- `GET /goals/calibrations/{runId}`: `{result: fullSavedRun}`. Unknown IDs and
  another user's IDs both return 404.
- `GET /goals/strategies`: typed definitions and `supports_calibration`, used by
  the new-run selector. `latest_calibration` summaries remain for compatibility.
- `GET /goals/strategies/{strategyId}/calibration`: compatibility endpoint for
  the latest-started successful run, or `{result: null}`. Unknown strategies
  return 404. Neither compatibility endpoint drives the history/report UI.
- `POST /goals/calibrate`: explicitly calculate and save a new generated batch:

```json
{
  "mode": "random",
  "strategy": {
    "id": "buy_and_hold_single_instrument",
    "parameters": {"instrument": "IE00B4L5Y983"}
  },
  "scenario_count": 1000,
  "min_horizon_months": 3,
  "max_horizon_months": 24,
  "lookback_months": 12,
  "simulation_method": "block_bootstrap",
  "block_size": 10,
  "start_date": null,
  "end_date": null,
  "seed": 42
}
```

Count is 10–5,000, horizons ordered within 1–120, lookback 3–120, and seed is
nullable/optional uint32. `simulation_method` defaults to `"standard"` with
`block_size: null`; `"block_bootstrap"` requires a strict integer `block_size`
from 1 to 60. A block size with standard Monte Carlo is rejected. Integer fields
reject booleans/fractions/strings. Extra
fields, manual money inputs and invalid strategies/parameters are rejected.
Acquired membership and acquisition state are rechecked before calculation.

Results include unique `id` and snapshotted `strategy_name`, echo `strategy`
and canonical `settings` (including simulation method and block size), with `calculated_at`, actual
`seed`, path counts, `method: "walk_forward"`, `data_as_of`, SHA-256
`history_fingerprint`, history bounds, candidate/scored/distinct-origin counts,
`generation` policy metadata, Brier/ECE, mean predicted/observed rates, all ten
`calibration_bins`, `forecasts`, `excluded_origins`, `skipped_counts` and warnings.
Requested scenarios equal scored plus excluded cases. Bins use actual predictions.
New `generation` metadata has `method: "independent_goals_contribution_solver"`,
`version: 2`, `solver_simulation_paths`, capital bounds, `goal_max_eur`,
`goal_rule: "above_starting_capital"` and probability bounds. It has no
`target_simulation_paths` or random monthly-funding range.

`calibration_runs` holds one immutable document per successful calculation with
server-authenticated ownership. Full result and summary are inserted atomically.
Identical settings and seeds still produce different run IDs; concurrent runs
are all retained, even when an earlier request finishes later. Owner-scoped
indexes support summary projections and latest-run reads without loading audits.
There are no update/delete run endpoints or automatic background calculations.
Older saved reports without simulation settings still display Standard Monte Carlo.
Reports using `training_quantiles_independent_streams` are labeled **Legacy ·
simulated targets**: they randomly generated monthly funding and selected goals
from simulated wealth. Their scores remain readable and unchanged, but are not
comparable to the new policy. **Run again** copies form settings and runs the new
policy, with an explicit warning that the scenarios differ even with the same
seed; it never overwrites the original report.

Existing `strategy_calibrations` latest results are imported lazily for their
authenticated owner, using deterministic `legacy-…` IDs and insert-only upserts.
Repeated reads/imports do not duplicate or alter them; the old collection remains
untouched. Only the previously retained latest result can be recovered—results
already overwritten by the old implementation cannot be reconstructed.

No evaluable cases returns 422, not a zero score. Work is bounded at 20,000 saved
dates, 600 available monthly origins and 30,000 simulated monthly periods counting
both independent streams and the maximum assigned horizon at each origin. Limits
reject excess work instead of silently truncating or retrying favorable cases.

Implementation: `goal_calibration.py` (shared math/history), `random_calibration.py`
(generation), `calibration_results.py` (persistence), `goal_strategies.py` (typed
`calibrate` callback), `goal_planner.py` (routes), and
`frontend/src/StrategyCalibration.jsx` (history, new-run form and saved report).
