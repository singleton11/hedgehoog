# On-demand Marketstack acquisition

## Decisions

- Search the existing Mongo `etfs` catalogue, deduplicated by ISIN using the latest snapshot. ISIN is the stable application instrument ID.
- Initial acquisition requests history from the catalogue inception date, not an assumed one-year window. The account now has a 10,000-request monthly paid allowance; local configuration is set accordingly, while installation defaults remain disabled. Plan/listing coverage can still restrict history; never equate HTTP success with complete since-inception coverage.
- First acquisition needs explicit quota authorization, but no manual symbol/MIC. Search `/v2/tickerslist` for the catalogue ticker and select the first named exact `TICKER.suffix` result with EOD support and a valid four-character `stock_exchange.mic`, in provider order. Do not accept substring/prefix lookalikes, unnamed results, bare tickers or infer MIC from the suffix. Persist mapping per ISIN in `instrument_state`, including lookup source/query/name/time/row, before downloading tickerinfo/EOD; reuse on updates, backfills and download retries. This requested heuristic is not independent ISIN verification. Provider ISIN mismatches are retained rather than blocking collection; identity reconciliation is deferred. An optional paired symbol/MIC override remains possible before quotes exist; stored quotes lock the listing.
- Only explicit acquisition requests consume provider quota. Search, details, polling and charts read Mongo. No scheduled refresh and no provider calls from GET routes.
- Celery owns acquisition. Durable Mongo job status, atomic duplicate suppression and worker leases prevent duplicate clicks/redeliveries from normally charging twice. Provider failures do not automatically retry; quota reservations are conservative and durable. A local configurable monthly request budget is independent of the provider dashboard and cannot account for external usage.
- Normal updates request dates after the last quote of the last fully processed range. Failed ranges do not advance that watermark. Explicit older-history backfill is separate to avoid repeatedly spending credits on inaccessible history. An empty response must not advance beyond the last observed quote: providers may publish late.
- `instruments`: append-only tickerinfo observations with `instrument_id`, listing, job ID, exact UTC `collected_at`, UTC `collection_date` and the full provider `data`. This is knowledge time, not retroactive historical fundamentals.
- `quotes`: immutable observations keyed by instrument, listing, quote date and job ID, with exact collection time/date and all raw/adjusted provider fields. Retry writes are idempotent. Reads select the latest observation for each date; an optional `as_of` bounds knowledge time.
- Market-data ingestion is permissive, with cleanup explicitly deferred. Do not block on missing/null/oddly typed numbers, zero/negative values, OHLC relationships, identifier mismatches or dates/order/duplicates. Save complete parsed envelopes in `raw_eod_pages` keyed by job/offset before indexing; re-use saved pages on worker recovery. Project objects with usable calendar dates into `quotes`; first occurrence per job/date wins and all duplicates remain in raw pages. Other rows remain raw-only and increment `unindexed_rows`. Keep only transport, JSON-object/data-array envelope, explicit authorization, lease and quota safeguards. No new quality flags or quality-based chart filtering.
- Chart unadjusted OHLC. Preserve nullable adjusted fields as provided; the live sample has missing adjusted OHLC on older bars and null price currency. Never substitute fund currency for unknown listing price currency, or mix raw/adjusted candles silently. Incremental retrieval does not refresh earlier corporate-action adjustments.
- Automated tests use provider fixtures only. A bounded live `WEBN` search verified the response shape and selection (`WEBN.DE` / `XETR`), now captured as an offline fixture. No automated tests spend live quota.
- Lookup uses `limit=1000`, follows pages only until a match, advances by actual returned row count, and consumes the same atomic monthly/job request limits. No match or provider failure ends the job without EOD; no failed/empty resolution is cached. A crash after persisting the mapping reuses it on redelivery.

## HTTP contract (authenticated, frontend adds `/api`)

- `GET /instruments/search?q=...&limit=15` -> `{items: [{instrument_id, isin, name, ticker, asset_class, currency}]}`. At least two characters, bounded length; escaped case-insensitive name/ticker/ISIN matching.
- `GET /instruments/{isin}` -> `{instrument_id, catalogue, listing, listing_resolution, profile, acquisition, summary, provider_configured, budget}`.
  - `catalogue`: complete latest ETF catalogue document without Mongo `_id`.
  - `listing`: `{symbol, exchange}` or null.
  - `listing_resolution`: `{source, query, name, collected_at, data}` for an automatic mapping, otherwise null.
  - `profile`: `{collected_at, collection_date, data}` or null.
  - `acquisition`: latest public job or null; statuses `queued`, `running`, `succeeded`, `failed`.
  - `summary`: `{quote_count, first_date, last_date, requested_from, history_status, warning}`; history statuses `not_requested`, `empty`, `partial`, `available`. `available` means the returned coverage starts near inception, not proof of every historical trading session.
  - `budget`: `{limit, used, remaining, month}`; local conservative accounting, not the provider's dashboard balance.
- `POST /instruments/{isin}/acquisitions` JSON `{confirmed: true, mode: "update" | "backfill"}` (mode defaults to update), optionally with both `symbol` and `exchange` for manual override -> HTTP 202 `{job: ...}`. First update performs initial download. Active duplicate returns the existing job. Listing is fixed once quotes exist; no-data failures may be corrected. Broker publish failure is recorded and returned as 503.
- Public job fields: `{id, instrument_id, status, phase, mode, requested_at, started_at, finished_at, pages, rows, flagged_rows, unindexed_rows, calls, error, warning}`. `error` is a sanitized string or null. Date/timestamp values use ISO strings. No credentials or provider request URLs in responses/logs.
- `GET /instruments/{isin}/quotes?limit=1000&offset=0[&as_of=ISO_TIMESTAMP]` -> `{items, total, limit, offset, as_of}`; ascending date. The first page supplies a server-generated knowledge-time cutoff; reuse it on subsequent pages instead of relying on the browser clock. Each item includes `date` (YYYY-MM-DD), `collected_at`, `quality_flags` (legacy metadata only, not a filter), unadjusted and adjusted OHLC/volume and preserved provider fields. Numeric prices/volumes are serialized as exact strings; null, missing and unexpected JSON shapes are retained. The chart converts at the rendering boundary, plotting finite numeric OHLC unchanged and skipping only rows it cannot draw. Pagination uses available totals/limits as hints, stops on empty pages and remains bounded by the job request cap.

## UI

Authenticated workspace with debounced, keyboard-accessible autocomplete and URL-addressable instrument pages. Explain automatic lookup or saved mapping reuse and require quota authorization before Request Data; include lookup in estimates only when uncached. A manual override is optional before quotes exist. Show plan/history coverage warnings without assuming a Free plan. Show queued/running progress; poll Mongo-backed detail endpoint with cancellation and error handling. Once data arrives, render candles, coverage/collection dates, and complete catalogue/tickerinfo in expandable structured sections. Preserve older data while an update is in progress or fails. Provide Update Data and separate Retry Older History for partial coverage. Never automatically POST an acquisition when navigating, polling or mounting.
