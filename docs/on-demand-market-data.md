# On-demand Marketstack acquisition

## Decisions

- Search the existing Mongo `etfs` catalogue, deduplicated by ISIN using the latest snapshot. ISIN is the stable application instrument ID.
- Initial acquisition requests history from the catalogue inception date, not an assumed one-year window. The account now has a 10,000-request monthly paid allowance; local configuration is set accordingly, while installation defaults remain disabled. Plan/listing coverage can still restrict history; never equate HTTP success with complete since-inception coverage.
- First acquisition needs explicit quota authorization, but no manual symbol/MIC. Search `/v2/tickerslist` for the catalogue ticker and select the first named exact `TICKER.suffix` result with EOD support and a valid four-character `stock_exchange.mic`, in provider order. Do not accept substring/prefix lookalikes, unnamed results, bare tickers or infer MIC from the suffix. Persist mapping per ISIN in `instrument_state`, including lookup source/query/name/time/row, before downloading tickerinfo/EOD; reuse on updates, backfills and download retries. This requested heuristic is not independent ISIN verification. Provider ISIN mismatches are retained rather than blocking collection; identity reconciliation is deferred. An optional paired symbol/MIC override remains possible before quotes exist; stored quotes lock the listing.
- Only explicit acquisition requests consume provider quota. Search, details, polling and charts read Mongo. No scheduled refresh and no provider calls from GET routes.
- Celery owns acquisition. Durable Mongo job status, atomic duplicate suppression and worker leases prevent duplicate clicks/redeliveries from normally charging twice. Provider failures do not automatically retry; quota reservations are conservative and durable. A local configurable monthly request budget is independent of the provider dashboard and cannot account for external usage.
- Normal updates request dates after the last quote of the last fully processed range. Failed ranges do not advance that watermark. Explicit older-history backfill is separate to avoid repeatedly spending credits on inaccessible history. An empty response must not advance beyond the last observed quote: providers may publish late.
- `instruments`: append-only tickerinfo observations with `instrument_id`, listing, job ID, exact UTC `collected_at`, UTC `collection_date` and the full provider `data`. This is knowledge time, not retroactive historical fundamentals.
- `quotes`: immutable observations keyed by instrument, listing, quote date and job ID, with exact collection time/date and all raw/adjusted provider fields. Retry writes are idempotent. Reads select the latest observation for each date; an optional `as_of` bounds knowledge time.
- Market-data ingestion is permissive, with cleanup explicitly deferred. Do not block on missing/null/oddly typed numbers, zero/negative values, OHLC relationships, identifier mismatches or dates/order/duplicates. Save complete parsed envelopes in `raw_eod_pages` keyed by job/offset before indexing; re-use saved pages on worker recovery. Project objects with usable calendar dates into `quotes`; first occurrence per job/date wins and all duplicates remain in raw pages. Other rows remain raw-only and increment `unindexed_rows`. Keep only transport, JSON-object/data-array envelope, explicit authorization, lease and quota safeguards. No new quality flags or quality-based chart filtering.
- Chart unadjusted OHLC. Preserve nullable adjusted fields as provided; the live sample has missing adjusted OHLC on older bars and null price currency. Never substitute fund currency for unknown listing price currency, or mix raw/adjusted candles silently. Incremental retrieval does not rewrite provider-adjusted fields. Derived calculations instead use a separate split-corrected raw-close series (see below).
- Automated tests use provider fixtures only. A bounded live `WEBN` search verified the response shape and selection (`WEBN.DE` / `XETR`), now captured as an offline fixture. No automated tests spend live quota.
- Lookup uses `limit=1000`, follows pages only until a match, advances by actual returned row count, and consumes the same atomic monthly/job request limits. No match or provider failure ends the job without EOD; no failed/empty resolution is cached. A crash after persisting the mapping reuses it on redelivery.

## Split history and derived prices

- Each explicit initial/update/backfill job also requests paginated `/v2/splits` for the full saved symbol (not its bare ticker), inception or earlier saved quote through yesterday UTC. Even a no-new-quotes update refreshes historical actions. One profile, one split page, one price page is typically three calls; automatic listing lookup adds at least one. Pagination uses the same monthly quota, job cap and lease protections.
- `raw_split_pages` preserves complete exact-number envelopes by job/offset before validation, allowing database recovery without paying again. `split_snapshots` publishes listing-scoped, complete normalized action histories only after all pages succeed. Duplicates with identical date/factor count once; conflicting, invalid, out-of-range or wrong-symbol actions fail the job without advancing the price watermark. Split pagination that ends before its declared total also fails. Evidence and raw quotes remain available.
- Statistics, observed trailing-year returns, Monte Carlo and both calibration modes use `split_adjusted_close`, never a rewritten quote field. Multiply raw closes by cumulative split factors effective on/before each date: 25 means 25 new shares per old share, 0.5 means a reverse split. Ratios equal backward-adjusted returns, but future actions cannot rescale past training prefixes. An action on a date without a candle still takes effect. Never multiply `adj_close` by split factors. Cash distributions are not reinvested.
- Each complete provider snapshot replaces the prior provider action set, including provider corrections/removals. Separately saved manual splits survive these updates. Snapshot identity and active manual-entry IDs invalidate statistics even when quote counts do not change. Reads and calculations are Mongo-only. Incomplete/failed attempted split downloads make derived prices unavailable rather than pretending a split is a crash; legacy history not yet refreshed retains its old basis with an update warning. Raw quote/chart reads are unchanged. Saved simulation/calibration reports remain immutable; recalculate to use corrected data.
- HTTP success cannot prove provider action coverage is complete. No price-jump heuristic or hard-coded SPYI.F correction is used. Update the instrument explicitly to acquire its provider split history, or add a verified missing action through **Market data → Splits → Add manual split** on the ETF page.

### Manual splits

- After quotes are saved, enter the issuer's effective date (ex-date) and **new shares per old share**: `25` for 25-for-1, `0.5` for a 1-for-2 reverse split. An optional source/note records supporting evidence. Dates must be valid, no later than today UTC, and not before a known inception date. Factors are exact decimal strings (up to 32 characters), between `0.000000001` and `1000000000`, excluding `1`.
- These authenticated corrections are shared instrument data, scoped to the saved ISIN/symbol/MIC, not a user's portfolio. They consume no provider quota and work with provider configuration disabled. They correct derived statistics, inventory metrics, new simulations and calibration only. Raw quote/chart fields, portfolio share balances and immutable saved reports are unchanged; recalculate reports to use new corrections.
- `manual_splits` stores immutable entry IDs, exact factors, notes, creation time/author and removal time/author. Only one active manual entry per listing/date is allowed (atomic partial unique index). Correct mistakes by confirming removal, then adding a replacement. Removed records remain for audit and historical knowledge-time reads.
- Manual/provider entries on the same date with equal factors apply once. Adding a different factor over an existing provider action returns `409`. A later provider update that conflicts with a manual entry makes derived returns unavailable with an explicit conflict message; remove/correct the conflicting evidence rather than silently choosing a factor. Provider updates/removals never erase a manual entry.
- With legacy quotes and no provider snapshot or attempted download, manual-only normalization is allowed with an explicit incomplete-history warning. Manual entries do not certify complete coverage or bypass existing failed/incomplete provider-download and coverage checks.
- `GET /instruments/{isin}/splits[?as_of=<timezone-aware timestamp>]` returns `{instrument_id, listing, manual, provider, error}`. Manual items contain `{id, date, factor, note, created_at}`; provider items contain `{date, factor}`. Historical reads select manual entries known and not yet removed at the cutoff.
- `POST /instruments/{isin}/splits` accepts `{id: <client UUID>, symbol, exchange, date, factor, note?}` and returns `201 {item}`. The listing must match saved quotes. Repeating the same UUID/payload returns the same item without a duplicate; changing its payload or retrying a removed UUID returns `409`. A separate UUID on an already occupied date also returns `409`.
- `DELETE /instruments/{isin}/splits/{id}` returns `204`, including retries. The immutable ID means a delayed delete cannot remove a replacement. Reads and writes never call the provider. The UI reconciles uncertain writes by reading saved state, retains the add request ID for an explicit retry, and refreshes statistics after save/removal.

## HTTP contract (authenticated, frontend adds `/api`)

- `GET /instruments/budget` -> `{limit, used, remaining, month}`; current global local-budget accounting from Mongo, available without selecting an instrument. Does not consume provider quota.
- `GET /instruments/search?q=...&limit=15` -> `{items: [{instrument_id, isin, name, ticker, asset_class, currency}]}`. At least two characters, bounded length; escaped case-insensitive name/ticker/ISIN matching.
- `GET /instruments/acquired?limit=20&offset=0` -> `{items, total, limit, offset}`; authenticated, Mongo-only inventory. Limit is 1–100, offset is nonnegative. One row per ISIN with a saved tickerinfo observation (the worker saves this before any EOD data), including partial/failed acquisitions; queued jobs and mappings alone do not qualify. Sort by latest profile `collected_at` descending, then ISIN ascending. Each item has `{instrument_id, isin, name, ticker, listing, collected_at, quote_count, first_date, last_date, annualized_mean_log_return, annualized_volatility, historical_year_return, historical_year_start_date, historical_year_end_date, historical_year_price_basis, historical_year_volatility, historical_year_volatility_start_date, historical_year_volatility_end_date, historical_year_volatility_price_basis, historical_year_volatility_return_count}`. Name/ticker come from the latest catalogue snapshot; quote coverage counts distinct dates for the latest saved profile's listing. Annual estimates are nullable numeric fractions, using the same log-return model and 252-day annualization as instrument statistics. Separately, `historical_year_return` is the actual simple trailing 12-month price change ending at the latest saved quote (`end / start - 1`), with endpoint dates and price basis. The start quote must be on/before the calendar anniversary and no more than seven days earlier; February 29 clamps to February 28. A complete split snapshot supplies split-corrected raw closes at both endpoints; legacy history without splits prefers provider-adjusted endpoints, otherwise raw closes. Insufficient history, invalid endpoints, mixed known interval currencies or non-finite ratios yield null historical fields, not extrapolated growth. `historical_year_volatility` separately annualizes the sample standard deviation of daily log returns within the trailing year (`sqrt(252 * variance)`), requiring full-year saved coverage and at least two usable daily returns. It uses split-corrected raw closes when a complete split snapshot is available, or one consistent provider-adjusted/raw basis for legacy history within that window, skips missing-weekday intervals, and rejects known mixed currencies. Its separate window dates, basis and usable-return count are included for the tooltip; all five volatility fields are null if unavailable. The Statistical columns still use all saved history. See [historical return and volatility details](goal-planner.md#historical-yearly-return-inventory). Cached estimates are refreshed lazily from saved prices for the requested page only; no provider requests or per-instrument frontend reads are made. Estimates are unavailable if there are too few usable returns or the statistics listing does not match the displayed profile. No full provider payloads or catalogue holdings are returned. Offset pagination reflects live saved data; refresh restarts at the first page.
- `GET /instruments/{isin}` -> `{instrument_id, catalogue, listing, listing_resolution, price_currency_override, profile, acquisition, summary, provider_configured, budget}`.
  - `catalogue`: complete latest ETF catalogue document without Mongo `_id`.
  - `listing`: `{symbol, exchange}` or null.
  - `listing_resolution`: `{source, query, name, collected_at, data}` for an automatic mapping, otherwise null.
  - `price_currency_override`: manually saved `EUR`, `USD`, `CHF`, `GBP` or `RUB`, otherwise null. Current shared instrument metadata (also current on `as_of` reads), stored separately in `instrument_state`; survives acquisitions and does not alter fund currency or raw provider observations.
  - `profile`: `{collected_at, collection_date, data}` or null.
  - `acquisition`: latest public job or null; statuses `queued`, `running`, `succeeded`, `failed`.
  - `summary`: `{quote_count, first_date, last_date, requested_from, history_status, warning}`; history statuses `not_requested`, `empty`, `partial`, `available`. `available` means the returned coverage starts near inception, not proof of every historical trading session.
  - `budget`: `{limit, used, remaining, month}`; local conservative accounting, not the provider's dashboard balance.
- `PATCH /instruments/{isin}/price-currency` JSON `{price_currency: "EUR" | "USD" | "CHF" | "GBP" | "RUB"}` -> `{price_currency_override}`. Requires authentication, an existing catalogue instrument and an allowed browser origin. Only these five exact codes are accepted; unknown fields are rejected. Mongo-only save, no provider request or quota use.
- `POST /instruments/{isin}/acquisitions` JSON `{confirmed: true, mode: "update" | "backfill"}` (mode defaults to update), optionally with both `symbol` and `exchange` for manual override -> HTTP 202 `{job: ...}`. First update performs initial download. Active duplicate returns the existing job. Listing is fixed once quotes exist; no-data failures may be corrected. Broker publish failure is recorded and returned as 503.
- Public job fields: `{id, instrument_id, status, phase, mode, requested_at, started_at, finished_at, pages, rows, flagged_rows, unindexed_rows, calls, error, warning}`. `error` is a sanitized string or null. Date/timestamp values use ISO strings. No credentials or provider request URLs in responses/logs.
- `GET /instruments/{isin}/quotes?limit=1000&offset=0[&as_of=ISO_TIMESTAMP]` -> `{items, total, limit, offset, as_of}`; ascending date. The first page supplies a server-generated knowledge-time cutoff; reuse it on subsequent pages instead of relying on the browser clock. Each item includes `date` (YYYY-MM-DD), `collected_at`, `quality_flags` (legacy metadata only, not a filter), unadjusted and adjusted OHLC/volume and preserved provider fields. Numeric prices/volumes are serialized as exact strings; null, missing and unexpected JSON shapes are retained. The chart converts at the rendering boundary, plotting finite numeric OHLC unchanged and skipping only rows it cannot draw. Pagination uses available totals/limits as hints, stops on empty pages and remains bounded by the job request cap.

## UI

The app header shows the local quota budget beside the logo and user info on every authenticated page. It refreshes from Mongo every five seconds, displays an unavailable state on read failure, and stops polling at sign-out. On narrow screens it wraps below the logo/account controls.

Authenticated workspace with debounced, keyboard-accessible autocomplete on a dedicated Add ETF page (`#/add`) and URL-addressable instrument pages. An Add ETF button above the home table opens search; selecting a result opens its details for explicit acquisition. The list and detail pages do not display catalogue search; the goal planner uses strategy parameters with an acquired-universe instrument selector, never catalogue search. The home screen lists Acquired ETFs with saved listing, Annual return and Annual volatility percentages (Unavailable when missing), distinct quote count/range and profile collection age in elapsed days (exact UTC date/time in a hover tooltip), including explicit profile-only and empty states. Pagination and list reloads read Mongo only; returning from details reloads the list. A Market data column has an Update market data button for each ETF and Update all in its header. Both require explicit quota consent. Update all captures every inventory page before submitting incremental-update jobs, so updates cannot reorder the list being traversed. It skips ETFs whose latest profile collection age displays as 0 days ago (less than 24 elapsed hours, not calendar-date equality) and reports how many were skipped. Unknown collection times remain eligible; individual row updates can still refresh recent data. Keep the page open until submission finishes; already queued jobs continue on the worker after navigation. Row statuses poll Mongo only, saved values remain visible, and terminal jobs reload the inventory. Uncertain submissions reconcile via GET without automatically retrying POST; bulk submission stops on shared/network failures and reports unsubmitted ETFs. Explain automatic lookup or saved mapping reuse and require quota authorization before Request Data; include lookup in estimates only when uncached. A manual override is optional before quotes exist. Keep copy concise: show coverage status and dates without warning notices. Preserve actionable errors, disabled-action explanations and quota consent; technical explanations and raw metadata are expandable. Show queued/running progress; poll Mongo-backed detail endpoint with cancellation and error handling. Once data arrives, render candles, coverage/collection dates, and complete catalogue/tickerinfo in expandable structured sections. Preserve older data while an update is in progress or fails. Provide Update Data and separate Retry Older History for partial coverage. Never automatically POST an acquisition when navigating, polling or mounting. Only when loaded prices have unknown currency, a Price currency dropdown offers EUR, USD, CHF, GBP and RUB with an explicit Save currency button and error feedback. It stays hidden during quote loading/errors and when provider prices determine the currency or a manual choice is already saved. Successful saves replace the selector with the currency label and persist on revisit. The manual setting takes precedence in chart labels and hover text, not the raw quote disclosure; it only labels prices and does not convert amounts. Missing currency stays unknown until the user saves a choice.
